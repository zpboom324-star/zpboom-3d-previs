# ZPboom.AI · 3D 预演导演

把镜头、走位和动作顺序中能提前发现的问题放到生成前处理。交付可修改的 3D 预演工程、可复用配置和生成交接资料；效果与尝试次数取决于分镜、素材、宿主和视频模型。

## 入口与交付

判断任务处于哪一步：新建预演、修改已有工程，还是整理生成参考。用户给了现成 HTML/配置时，在它的副本上继续，保留相机与素材绑定；不要重新搭一套无关剧情。只需改提示词时，直接完成对应阶段。

复用会话里已有的时长、画幅、分镜和素材。缺少足以影响制作的事件或主体时集中询问；风格、示例机位等可先用明确标注的假设做最小预演。没有图片仍可用有标签的几何代理先走通空间。

### 开工确认（新建预演工程前必做，避免返工）

先读完用户给的分镜，再用 **一次 AskUserQuestion** 把下面 4 个问题一起问（每题第一个选项是推荐项）。用户在请求里已经说明的题不问，4 题都说明了就直接开工。问完再动手，不要先搭场景再回头问。

| 题目 | 选项 | 为什么要先问 |
| --- | --- | --- |
| 人物白膜 | 精细白膜（四肢、眼带、显示道具）/ 简化胶囊（球头 + 胶囊身体，无四肢、不显示道具，生成时表演更自由） | 决定参考视频里人物长什么样、道具出不出现 |
| 预演画面亮度 | 明亮可读，夜景、低调光写进提示词（推荐）/ 按分镜影调做暗 | 暗场预演容易被视频模型读黑，做完再提亮要重调灯光 |
| 分镜机位和空间冲突时 | 保持空间真实，机位就近调整并在 storyboard.md 标注（推荐）/ 严格按分镜机位，必要时改场景尺寸 | 窄通道、室内等场景经常装不下分镜写的机位，事后改要重做走位 |
| 这次做到哪一步 | 只做预演，看过再说 / 预演 + 导出参考视频 / 预演 + 参考视频 + 生成交接（分段、提示词、上传清单） | 决定交付范围，避免做多或做少 |

- 动作方式**不在这里问**：没说明就按下文默认方式 1。
- 画幅、时长、角色、事件从分镜里读；分镜确实没写、又会影响制作时，才在同一次提问里补一题（总数不超过 4 题，挤不下就把「做到哪一步」放到预演完成后再问）。
- 回答用 `new_project.py --figure jointed|pill --lighting readable|mood --camera space|storyboard --deliver previs|video|handoff` 记进 `revision-log.md` 的「开工确认」。之后改同一工程一律沿用，用户改口时更新这一节。
- 按回答执行：选了「保持空间真实」，每处机位偏离都写进 storyboard.md 末尾；选了「按分镜影调」，交付时提醒导出时用「提亮参考」；「做到哪一步」完成后再问下一步，不要自作主张多做。

**人物白膜（两种，开工确认时问）：**

| | 精细白膜（jointed） | 简化胶囊（pill） |
| --- | --- | --- |
| 外形 | 球头 + 眼带、可弯曲方块躯干、两节胶囊四肢，显示道具 | 球头紧贴与头同直径的胶囊身体（走跑时笔直，只在下蹲、坐下时弯曲），无四肢、无五官、不显示道具，底端离地约 16 厘米悬浮 |
| 适合 | 要看清手部接触、四肢动作，或要拿去后期微调动作模型 | 拿参考视频去生成：视频模型不会照抄白膜的僵硬关节，表演发挥空间更大 |

- 两种只换外形、不改动作：骨架、IK、道具挂点照常计算，胶囊身体整体跟着重心前倾、摇晃、倒地，下蹲和坐下时才弯曲。
- 在「开工确认」里问用户选哪种；之后同一工程沿用，网页顶栏「精细白膜 / 简化胶囊」下拉可随时一键切换（可撤销，保存进 `world.figure`）。

**动作方式（两种，由用户选；没说就用方式 1）：**

| | 方式 1 · 关键帧直接做（快速版） | 方式 2 · 混合（关键帧 + 动捕） |
| --- | --- | --- |
| 人物动作 | 只用姿态库关键帧，加 IK 贴合、步态、呼吸微动 | 走位、机位、道具、接触用关键帧；摔倒、打斗、舞蹈等全身动作换成 FBX 动捕片段 |
| 需要的素材 | 不需要 | 动作文件（Mixamo 免费动作库需用户自己登录下载，或手机拍视频转动作导出 FBX） |
| 适合 | 走位、对峙、机位节奏为主，或只要粗预演的项目 | 重心、惯性、力量感要像真人的全身动作 |
| token / 时间 | 最省：不读动捕文档、不找动作、不调片段时机 | 更多：要挑片段、对起点和速度、多一轮核对 |

- 用户已经说明时照办：说“直接做 / 不用太精细 / 关键帧 / 快速”就是方式 1；说“动捕 / Mixamo / FBX / 动作文件”就是方式 2。
- 没说明时**默认方式 1**，不用为这个专门提问，也不要自己改成混合。分镜里有摔、打、舞这类全身动作时，交付时用一句话提醒可以升级到方式 2。
- 建工程时用 `new_project.py --motion keyframe|mixed` 记下选择（写进 `revision-log.md`，方式 2 还会建好 `motions/` 和放文件说明）。之后修改同一工程沿用这个方式，除非用户要换。
- 方式 1：不读 [动作捕捉片段](references/motion-capture.md)，不搜索或下载动作，不写 `motions / clips`；关键姿态写在事件节点上，靠插值、步态和微动补中间。
- 方式 2：读 [动作捕捉片段](references/motion-capture.md)。动作来源两种：用户自己用手机拍视频，在网页「视频动捕」里本机识别（不用动捕设备、不用下载动作库）；或 FBX 动作文件，先列出每个动作需要的片段名和文件名请用户提供；文件没到时页面会自动用关键帧顶上，不要因此停工；文件放进来后再对片段起点、速度和接触。
- 两种方式随时可以互换：1 → 2 加 `motions` 和角色 `clips`；2 → 1 删掉 `clips`，关键帧本来就在。

完整项目通常包含：

- `index.html / app.js / styles.css / vendor/`：浏览器可运行工程。
- `scene.json`：时间线、机位和角色路径；页面导出的修改要写回项目配置。
- `asset-map.json`：角色—外观—专属道具—场景—上传标签绑定。
- `storyboard.md / revision-log.md`：分镜依据、改动和需要人工判断的点。
- `generation/`：分段计划、生成提示词、上传顺序和检查清单；实际视频另行录制。

## 1. 把分镜变成可验证的空间关系

读取 [导演流程](references/directing-workflow.md)。为每镜明确时码、事件、主体、起止机位、目标点、运动方向和前后状态。把“更有电影感”转成相机高度、距离、景别、目标位置、路径和节奏。

角色使用稳定 ID，外观和专属道具分开绑定。用户参考图只提供设计，不直接当作预演的相机位置、棚拍光线或人物站姿。多角色先确认谁在前、谁受袭、谁救援、道具属于谁。用事件和位置检查完成度，不以人物数量正确代替动作关系正确。

## 2. 搭建能修改的 3D 网页预演

本包的 [统一模板](assets/previs-starter/index.html) 已经包含通用引擎和界面：白膜人偶（默认；球头加长方形眼带、可弯曲的方块躯干加胸前名牌、两节胶囊四肢、不做手脚、关节留缝、每个角色一种纯色）和圆润人偶（可选）、白膜场景开关、全身持续微动与手持相机漂移、FBX 动作捕捉片段播放（见 [动作捕捉片段](references/motion-capture.md)）、姿态库、IK 接触、道具换手、结构动画、钢索 / 发光 / 电火花 / 灰尘特效、声音提示、当场编辑（画面里点选拖动人物 / 道具 / 场景物件、可开关的自动关键帧、时间线逐对象关键帧轨道、撤销重做、Ctrl+S 直接保存 scene.json、自动草稿；自由观察环绕 / 平移 / 飞行 / 聚焦、俯视平面图、镜头小窗、相机路径与取景框可拖、运镜微调、FOV 滑杆、镜头切分 / 删除 / 改名 / 拖切点）、天气系统（雨 / 雪 / 雾 / 风 / 阴天 / 地面湿 / 时间段 / 闪电，可上时间线，屋顶下不下雨）、姿态编辑（姿态库、14 个关节微调滑杆、手部接触选目标或拖小球，微调也能叠加在动捕片段上修正动作）、逐帧 MP4 导出、导出 Blender 工程（GLB 动画 + `blender_setup.py`），以及按配置自动生成的检查器。**新工程只写 `scene.json`，不改 `app.js / editor.js / viewtools.js / weather.js / index.html / styles.css`**，这样最省 token，效果也和完整手写一样。在新的项目目录复制模板：

```bash
python3 scripts/new_project.py --output "./my-previs" --title "我的短片" --duration 15 --fps 30 --aspect 16:9 --motion keyframe --figure jointed --lighting readable --camera space --deliver previs   # 后四项按「开工确认」的回答填；画幅可选 16:9 / 21:9 / 9:16 / 1:1 / 4:3 / 3:4；方式 2 用 --motion mixed
```

**界面固定用模板自带的 ZPboom 界面**（石墨色剪辑软件风格：顶栏只有「导出 MP4」一个主按钮，比例时间线带镜头 / 声音 / 逐对象关键帧轨道，逐帧与切镜控制，检查器分「角色 · 姿态 / 镜头 / 天气 / 说明」四页、选中卡片常驻）。不要为单个项目重新设计或改动 `index.html / styles.css`，也不要换配色或布局。遇到用旧界面或旧引擎做的工程，先备份，再升级到当前模板。确实需要改进界面时，改模板本身并升级所有工程，让界面保持一致。

加 `--empty` 会得到只有界面和引擎的空场景，适合整份重写 scene.json。坐标多、要批量计算时（例如弧线跳跃、环绕机位、倒塌台面上的落脚点），在工程的 `tools/` 里写一个生成 scene.json 的 Python 脚本；要告诉用户，在网页里导出修改后不要再运行这个脚本。

脚本路径相对于**本技能目录**，执行时先解析实际路径；项目输出位置按用户指定。Windows 若只有 `python` 或 `py`，替换解释器名。已有可用项目无需强行套模板。

模板自带一个 30 秒示范案例「影棚开拍前的忙碌日常」（斯坦尼康一镜到底、14 个角色，用到推门、道具传递、灯架升降、半环绕、穿越前景、登梯升高俯拍、布景灯全亮），必须按照用户分镜改写场景几何（`set`）、人物体型（`kinds`）、角色路径、道具、事件与镜头；仅改标题不算完成新项目。使用真正的 3D 几何、透视和遮挡，图片板可作设计参考。门、台阶、窗、倒塌结构都用 `set` 节点加 `rigs` 搭出来。分镜需要内置能力没有的东西时（车辆、布料、人群等），用 scene.json 的 `extensions` 挂一个工程内扩展模块，不要改通用引擎；同一种扩展在两个以上项目里用到时，再合并进模板。

模板绑定 Three.js r160，依赖随包携带，本地 HTTP 服务即可运行：

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory "./my-previs"
```

端口占用时换空闲端口，读取服务输出确认；`http://127.0.0.1:8000` 打开工程。若宿主的预览服务读不到项目目录（例如 macOS 隐私权限下 `~/Documents` 返回 404），改用 shell 在后台启动上面的命令，再用浏览器打开。模板使用 ES modules，不能把双击 `file://` 能打开当作已验证。现有 Three.js 工程沿用它的实际版本，不混用其他版本 API。

写 scene.json 前先读 [配置约定](references/scene-format.md)，里面有全部字段、人物部位、内置姿态、道具库、特效和焦段换算。所有运动由时间线采样，seek 到同一时间应得到同一画面；每镜相机重置局部时间，硬切不跨镜补间。模板界面已支持暂停、进度拖动、切镜、修改机位与目标、画面内拖动编辑、关键帧编辑、撤销重做、直接保存和干净画面。用户在网页里改过并保存后，scene.json 就是最新版本：之后改工程要先读它，不要再运行 tools/ 里的生成脚本覆盖。适配用户画幅，录制前确认实际 canvas 尺寸。

## 3. 按时间码迭代与检查

人物动作按选定的方式做（见上文「动作方式」，没说就是方式 1）：方式 1 只用姿态库关键帧；方式 2 让打斗、舞蹈、摔倒这类全身动作播放动捕片段，关键帧负责走位、机位和接触，没有动作文件时自动退回关键帧。

多人接触（擒腕、箍抱、拍肩、抓取、双手持枪）用 `reachL / reachR` 指向对方或道具的部位；道具换手用 `props[].keyframes[].holder`；结构倒塌、开门用 `rigs`。接触是否到位，先用 `point()` / `getState()` 读世界坐标核对，再只对关键切点截小图确认构图，这样能少截很多图。

用户说“3–5 秒镜头左移一点”时，先定位该镜的**相机**，避免误移动角色；“A 往左一步”则改角色路径。使用场景左右/画面左右有歧义时结合画面说明，无法推断再问。

保留修改前配置，记录镜头 ID、时间段、改了哪个参数、复查结果。机位和走位等会互相影响，一次完成一个连贯修改并复查相邻切点；不替用户锁死迭代轮数。

```bash
python3 scripts/validate_scene.py "./my-previs/scene.json"
```

配置检查只发现结构、时码和引用错误，不能代替看画面。网页加载时还会做完整校验（未知姿态、引用了不存在的部位等会直接提示）。有浏览器能力时实际查看每镜起点、中间、终点和切点前后（截图可缩到 0.4 倍），检查黑屏、穿墙、目标出画、角色交换和道具漂移；试用暂停修改、导出再导入。`window.__ZPBOOM_PREVIS__` 提供确定性检查接口，见配置文档。无浏览器时明确只完成静态检查，不声称已看过预演。

## 4. 录制与整理生成参考

预演满意后读取 [生成交接](references/generation-handoff.md)。先保存配置，再导出参考视频。模板的「导出 MP4」按钮会逐帧渲染：按 1/fps 采样每一帧，用浏览器 WebCodecs 编码成 H.264，再用随包的 `vendor/mp4-muxer.mjs` 封装成 MP4，尺寸按画幅自动选择（16:9 为 1920×1080，21:9 电影宽银幕为 2520×1080，9:16 为 1080×1920）；点击后先弹出导出设置，可另选画幅（例如工程 16:9、导出 21:9，裁切或扩展）和清晰度（720p / 1080p / 4K），导出 Blender 同样适用。工程画幅在顶栏随时切换（可撤销），每个镜头还能单独设画幅（黑边）并显示其他画幅的取景参考线。它不掉帧，时长与配置一致，导出时自动隐藏网格、标签和工作光。浏览器不支持 WebCodecs 时，按钮会退回实时 WebM 录制，这种方式可能掉帧。`window.__ZPBOOM_PREVIS__.exportMp4({download: false})` 可以只编码不下载，用于验证结果（帧数、尺寸、文件头 `ftyp`）。页面在后台时浏览器会降速，导出变慢，但不影响帧的完整性。确认时长、画幅、切点和无 UI，才能称已得到参考视频。夜景、暗场不要把参考视频导黑：网页会提示过暗的镜头，用「镜头」页的「参考提亮 · 自动」，导出时选「提亮参考」（或「白膜平光」「深度图」），把夜晚等氛围写进生成提示词（见生成交接文档）。

用户要在 Blender 里继续做（精修机位灯光、换真实角色、交给动画师）时，读 [导出 Blender 工程](references/blender-export.md)：网页点「导出 Blender」得到带完整逐帧动画的 GLB（人物关节、道具、结构动画、每镜一台相机、灯光），再在 Blender 里运行工程自带的 `blender_setup.py` 生成 `.blend`（帧率、分辨率、镜头标记切相机、灯光强度、世界光都会设好）。有 Blender 时可以用命令行 `Blender -b -P blender_setup.py -- 文件.glb` 实际生成并检查；没装 Blender 时只能验证 GLB（`exportBlender({download: false})` 重新载入比对、`python3 blender_setup.py --check`），不要声称已生成或打开过 .blend。

整理素材绑定表后运行：

```bash
python3 scripts/prepare_generation.py --scene "./my-previs/scene.json" --assets "./my-previs/asset-map.json" --output "./my-previs/generation"
```

需要评估短段参考时可加 `--segment-seconds 15`。它按完整镜头分组，15 秒是规划目标，不是模型能力上限；这个脚本生成裁切计划和提示词，**不会自动裁出或生成视频**。跨段保持角色、道具、场景和动作状态，复杂事件不要从中间强拆。

提示词明确分工：预演约束机位、构图、空间、事件顺序；图片约束身份、服装、道具和场景设计；最终动作重新形成自然表演，不继承代理模型的僵硬步频、滑步、关节抽动或简化材质。上传标签必须由实际界面绑定，未绑定时保留有名称的占位并列出待办，不能编造 `Mixed 1` 等编号。

视频平台、模型版本和参考入口由用户实际可用环境决定。未核实的“样片模式”、API、最长时长、费用或兼容性不能写成事实。宿主能执行的本地工作继续完成；没有生成服务时交付参考包与操作步骤，不声称生成了最终 CG。
