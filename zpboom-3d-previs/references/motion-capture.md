# 动作捕捉片段（FBX）

预演角色可以直接播放真人动作捕捉数据，动作的重心、惯性和呼吸感会接近专业白膜预演。引擎把 FBX 骨骼动作映射到白膜人偶上，然后照常叠加 IK 接触（握枪、扣腕、箍抱仍然贴合）。

## 动作从哪里来（便宜到几乎免费）

1. **免费动作库（推荐先用）**：Mixamo 等。选好动作后下载设置：
   - Format：**FBX Binary (.fbx)**；Skin：**Without Skin**（文件小）或 With Skin 都可以；
   - Frames per Second：30；Keyframe Reduction：none；
   - 走、跑这类移动动作勾选 **In Place**（原地），移动路线由我们的关键帧控制。
2. **手机拍视频转动作**：用手机把要演的动作完整拍一遍（全身入画、光线充足、背景简单），上传到视频转动作工具（如 Rokoko Vision、DeepMotion 等，通常有免费额度），导出 **FBX**，骨骼命名选 **Mixamo** 或 Humanoid。
3. 价格、额度和导出选项以各工具官网为准；动作素材的使用授权由用户确认，素材文件不放进分享包。

## 放进工程

把 `.fbx` 放进工程的 `motions/` 文件夹，然后在 scene.json 里写：

```json
"motions": [{"id": "punch", "file": "motions/Punching.fbx", "clip": 0}],
"actors": [{"id": "A", "...": "...", "clips": [
  {"motion": "punch", "start": 3.2, "offset": 0.4, "speed": 1, "fadeIn": 0.2, "fadeOut": 0.3}
]}]
```

| 字段 | 含义 |
| --- | --- |
| `motions[].clip` | 文件里第几段动画（数字，从 0 开始）或动画名称 |
| `clips[].start` | 在全片第几秒开始播 |
| `clips[].offset` | 从动作片段的第几秒开始取（用来截掉开头的准备动作） |
| `clips[].end` | 可选，播到全片第几秒；不写就播完整段 |
| `clips[].speed` | 播放速度（慢动作写 0.5） |
| `clips[].fadeIn / fadeOut` | 与关键帧姿态之间的淡入淡出秒数 |
| `clips[].weight` | 0–1，与关键帧姿态混合的比例 |
| `clips[].loop` | 循环播放（站立呼吸、跑步循环） |
| `clips[].hold` | 播完后停在最后一帧（倒地、坐下后保持） |
| `clips[].rootMotion` | 是否带上动作里的水平位移；默认否，用关键帧控制走位更好对齐机位 |
| `clips[].override` | 不写 = 叠加在原关键帧上（原手部接触、微调、高度照旧生效）；`"pose"` = 覆盖姿态：片段期间原关键帧的手部接触、关节微调、身体高度和俯仰侧倾不生效，水平走位和朝向照旧；`"all"` = 完全覆盖：连走位和朝向也固定在片段起点（原地做动作），片段结束后按正常步速走回原关键帧路线再接上（不会瞬间滑回去）。原关键帧不删，片段之外照常 |

- 片段播放期间，角色的位置和朝向仍由关键帧决定，四肢、躯干、头和身体高低来自动作文件。
- 同一角色可以排多个片段，前后段用淡入淡出衔接；片段之外仍是关键帧姿态。
- 时间线的“关键帧”轨道会显示片段区间（浅蓝色条）。
- 动作文件还没放进工程时，页面照常打开，状态栏提示缺哪些文件，角色暂用关键帧姿态；文件放进去刷新即生效。
- 骨骼对不上时，页面会直接提示缺哪些骨骼。支持 Mixamo 命名及 LeftUpperArm / LeftLowerArm 一类常见别名。

## 视频动捕（本机识别，不用动捕设备）

用手机拍一段人做动作的视频，网页直接识别出关节，生成动作片段。视频只在本页处理，不上传。

**浏览器**：视频动捕请用 Chrome 或 Edge。Safari（实测 18.6）里识别模型推理会崩溃（`Aborted()`，GPU / CPU 都一样），打开对话框时会直接提示改用 Chrome / Edge；网页的其他功能 Safari 都能正常用。

1. 选中角色 →「角色 · 姿态」页 →「视频动捕：用手机视频生成动作…」。
2. 选视频，可截取一段（开始 / 结束秒数），点「识别动作」。识别时画面上叠骨架线，识别完可以拖滑杆逐帧检查。
3. **对比预览**：识别完，对话框右边会把动作临时套到「加到角色」选的那个角色上（白膜，正对角色的预览镜头），和左边原视频 + 骨架同一帧。点「▶ 对比播放」（或按空格）两边同步播放，拖滑杆逐帧对照；左上角标「着地 / 腾空 xx cm」，右下角是人偶脚底离地高度。预览只显示这个角色 + 浅灰地面 + 中性光（场景里的墙、柱子、别的角色和场景灯暂时隐藏，不会挡住，夜景也看得清）；预览不写进工程、不进撤销，换角色、调平滑 / 朝向会立即刷新；关掉对话框就恢复原样。
4. 「精细识别」（默认关）：换成 MediaPipe 精细版模型。摔倒、打斗、地板动作、四肢互相遮挡时，最难的几帧少认错（霹雳舞实测：深蹲腿画反、扫腿腿够不到脚这类错误精细版是对的），普通走动、站姿、手势和标准版几乎一样。识别慢 2–4 倍（GPU 约 72 对 33 毫秒 / 帧）。对比预览里看到人偶有几帧乱甩时再勾上，重新点「识别动作」。
5. 调「平滑」（越大越稳、越小越跟手）；「朝向对准正面」默认开：第一帧的身体朝向转成正对前方，之后的转身保留——角色面朝哪边由关键帧的 yaw 决定。
6. 「起点」：动作从工程第几秒开始，打开对话框时自动填当前播放头，可改，也可一键设「0 秒」「播放头」；连续给几个人加时起点保持不变。动作超出工程结尾的部分播不到，下方会提前提示（例如「从 28.6 秒开始只能播 1.4 秒」）。
7. 「原有动作」：这段时间角色原来的动作怎么处理——叠加（默认，原关键帧的手部接触、微调、走位和重叠片段仍生效）/ 覆盖姿态（原动作让位给动捕，站位朝向照旧）/ 完全覆盖（原地做动作）。下方提示会写出这段时间原有几个片段、几个关键帧；覆盖时重叠的旧片段自动让出这段时间（之前的截到起点、之后的从结尾接着播），原关键帧保留，片段外照常，Ctrl+Z 可撤销。
8. 「加到角色」：动作数据存进 scene.json 的 `motions`（`{"id": "...", "data": {"format": "zpboom-pose", ...}}`），并在该角色加一条 clip。之后和 FBX 片段一样调起点、速度、淡入淡出，叠加姿态微调和手部接触；Ctrl+S 保存，Ctrl+Z 撤销。

**自动贴地与跳起**：视频动捕片段每一帧套完动作后，会把人偶最低的那只脚放到角色所站的高度（关键帧 position 的 y：地面、台子、楼梯台阶）。源视频里的人和人偶腿长比例不同、或角色关键帧本身是蹲 / 坐类姿态时，不会再穿进地面或悬空。

跳起不会被压回地面：识别时同时从画面里算出每一帧的离地高度（存为 `data.lift`，每帧一个数，单位米）。做法是找脚落地的帧（脚踝在画面上停住、且是附近最低的位置）连成地面线，两次落地之间最低那只脚高出地面线多少，按身体在画面里的长度换成米；人偶上再按腿长比例缩放（人偶腿比视频里的人长，跳得也相应高一些）。走路、跳舞时总有一只脚踩着，算出来是 0；至少 3 帧高于 5 厘米才算离地，抖动不会被当成跳。要求手机固定不动、双脚完整入画：脚贴着画面下边或看不清的帧太多（超过 15%）时不开启跳起，只贴地，对话框会提示。手持晃动拍的跳跃高度不准。实测一段健身房连续跳跃弓步的真人视频：6 次腾空全部找出，时间和画面逐帧对上，高度 12–17 厘米。2.4.1 之前加的视频动捕片段没有 `lift`，只贴地不跳，想要跳起需重新识别一次。FBX 片段自带高度，不做贴地。

识别用的是 MediaPipe 姿态识别（标准版模型，可选精细版，Apache 2.0，都随包携带）：头、肩、肘、腕、胯、膝、踝共 15 个点，手指和脚掌不识别。动作默认是原地的（整体位移算不准），走位继续用关键帧。单目识别偶尔把正面认成背面，系统会按“朝向不可能一帧转 180°”自动修正。

**实时动捕（电脑摄像头）**：「角色 · 姿态」页「实时动捕：用摄像头跟着时间线表演…」，或在视频动捕对话框点「📷 摄像头实时」。摄像头每一帧都识别（取 640 宽），逐帧一欧元滤波（比录完后的平滑少一点，更跟手），同样做前后翻转修正和朝向对准正面，实时套到「加到角色」选的角色上。画面切换「左：镜头画面」时，左边是分镜相机在当前时间的画面（其他角色、机位照常），右边是摄像头 + 骨架；「左：摄像头 + 骨架」时右边是白膜预览。「● 录制」：3 秒倒计时后从「起点」按真实时间走时间线，「■ 停止」或播到工程结尾自动停；摄像头帧率不固定，停止后按工程帧率重新取样（取时间最近的帧，隔得超过 0.12 秒的当作没认出人，用前后帧补），然后交给和视频动捕完全相同的流程（平滑、踩地、跳起、对比回放、起点 / 原有动作、加到角色），动作数据的 `source` 里记 `camera: true`。认出人的帧不到一半时不允许加入。摄像头画面不上传、不保存，所以回放只画骨架。关闭对话框（关闭按钮、Esc）立即停掉摄像头轨道；在浏览器询问权限或载入模型时就关掉，拿到的摄像头也会马上关掉。浏览器要求安全地址：用 `http://127.0.0.1` 或 `localhost` 打开；Safari 同样不能用（识别模型崩溃）。页面在后台、浏览器不刷新画面时，会改用定时器继续识别，帧率会降低，所以录制时窗口要在前台。实测 Windows 11 + RTX 5060 Ti，Chrome 157 / Edge 157 识别用显卡，两种画面都稳定 30 帧/秒（跟满 30 帧/秒的输入），6 秒录制 185/185 帧认出人。

**拍摄建议**：手机固定不动；全身完整入画；光线充足；衣服和背景颜色分得开；画面里尽量只有一个人；正面或斜 45° 拍最准，纯侧面时手前后的深度容易判断错；手不要长时间藏在身后。

**实测**：一段夜晚篮球场跳舞的真人视频（22 秒 720p，彩色灯光）659 帧全部认出人，处理约 25 秒；交叉步、抬手、侧伸手臂、身体倾斜都能套到白膜人偶上，手臂朝镜头方向伸出时幅度会偏小（单镜头看不准前后深度）。识别对象必须是真人：白膜人偶这类没有五官的模型拍成视频当输入，识别率和准确度会明显下降。
