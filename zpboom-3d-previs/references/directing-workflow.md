# 从分镜到可修改的预演

## 输入与最小可用结果

提取项目总时长、画幅、帧率、角色身份、场景连接、关键道具、镜头事件和起止状态。把已有素材列入 `asset-map.json`，保留原文件名对应关系；不能把一个角色定妆板里的多视图识别成多个人。缺参考时先保留角色 ID 和待绑定字段，不凭空生成上传编号。

每镜用一句可观察的事件描述，例如“B 从 A 左后侧绕出，看见门内目标，抬起自己的手电”，再给出：

| 要素 | 要写清什么 |
| --- | --- |
| 机位 | 位置 XYZ、相机高度、目标点、FOV；过肩时前景是谁 |
| 路径 | 从哪里到哪里、向哪个轴运动、哪一时刻减速或停下 |
| 主体 | 各角色的身份、队列、前中后景关系与道具拥有者 |
| 状态 | 门是否打开、道具谁拿着、动作是否完成，下一镜如何承接 |
| 检查点 | 谁应可见、谁不能被挡、路径是否穿墙、切点是否重复动作 |

Three.js 模板约定 Y 向上、单位米，默认相机看向目标点。不把“左移”直接理解为 X 减小：画面左侧与世界左侧可能不同。计算相机视线和右向量，必要时用画面示意确认。

## 迭代次序

先让一个关键镜头走通：场景代理、主体、机位、事件。再扩展剩余镜头。空间关系通过后再微调移动路径、加速减速、遮挡、抬手或开门等必要动作。模板自带多关节人物；需要判断手部接触时用 `reachL / reachR` 让手贴到目标部位，用道具的 `holder` 交接。用户指定已有 HTML 时优先复用其数据和交互。

场景复杂度服务于分镜。楼梯必须有正确台阶高度和进出口，门要按铰链/滑轨运动，过肩镜头要有前景肩部遮挡和可读的目标；远景无关设备可用简化盒体。平面图片不能替代需要绕拍、遮挡和视差的几何主体。

## 角色与道具连续性

角色固定 A/B/C 等 ID，与名字、外观图、道具 ID 分开。每个角色组内挂自己的道具，不能仅凭相同颜色推断身份。跨镜沿用同一对象和道具绑定；坐标、朝向、持握状态按剧情变化。确有交接道具的镜头要把“交出/接住”的时间写成事件，不能通过换绑偷换拥有者。

检查视线、运动方向与轴线。相邻硬切要能判断角色面对谁、从哪来、到哪去；确需越轴时使用交代镜头或明确的运动桥接。不要为了“顺滑”给硬切加跨镜相机插值，或把每镜全局时间当局部时间导致跳帧。

## 修改记录示例

```text
版本：v02
依据：用户要求 5–10 秒过肩镜头，让 A 和门同时可见。
修改：s02 相机 X +0.6m；target 指向 A 与门的中间；角色路径未改。
检查：5.0 / 7.5 / 9.967 秒及下一镜第一帧；A 未被 B 肩部遮住。
待确认：前景肩部占比是否合适。
```

“更有电影感”可拆成可执行变化：从齐胸平视变为 1.2m 低机位；FOV 从 60° 改为 45°并后移保持景别；先短暂保持主体再绕至侧面；在终点减速。具体数值来自项目，不能把示例当固定审美公式。

## 多人长片分段

先用一个代表性片段验证参考效果，再按平台实际限制和故事段落规划。30 秒多人片可评估拆成两个约 15 秒段落，这是起点，不是通用硬规定。优先在完整事件后切开；动作还在发生、道具正在交接时避免截断。某一镜超出目标时长，先人工判断是否调整分镜，不自动破坏镜头。

为每段写入起止状态：人物身份/位置/朝向、道具持有、门状态、光线和运动方向。需要衔接参考时可准备交界关键帧；若使用重叠片段，在最终剪辑中核对去重，不机械拼接两次相同动作。
