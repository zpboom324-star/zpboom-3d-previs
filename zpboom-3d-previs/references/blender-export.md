# 导出 Blender 工程

预演满意后，可以把整段预演交给 Blender 继续做：精修机位、灯光、换真实角色、用 EEVEE / Cycles 出更精细的参考画面，或交给动画师。分两步：

1. **网页里点「导出 Blender」**（顶栏，在「导出 MP4」左边）。浏览器下载 `<标题>_blender.glb`。
2. **用工程里的 `blender_setup.py` 生成 `.blend`**（需要 Blender 3.6 或更新版本，自带 glTF 导入插件）：
   - Blender 界面：顶部切到「Scripting / 脚本」工作区 → 文本编辑器「打开」`blender_setup.py` → 点 ▶ 运行。脚本自动在它所在文件夹、「下载」、「桌面」里找最新的 `*_blender.glb`。
   - 命令行：`blender -b -P blender_setup.py -- <标题>_blender.glb [输出.blend]`（macOS 的 blender 在 `/Applications/Blender.app/Contents/MacOS/Blender`）。
   - 默认在 GLB 旁边保存同名 `.blend`；同名文件已存在时另存为 `_v2`、`_v3`…，不覆盖已经在 Blender 里改过的工程。
   - 没装 Blender 时可以先检查 GLB：`python3 blender_setup.py --check <标题>_blender.glb`，列出帧率、镜头、焦距、灯光和动画通道。

## GLB 里有什么

导出按工程帧率逐帧采样（和导出 MP4 用同一套摆位逻辑，只是不渲染，30 秒工程约 2 秒导完）：

| 内容 | 怎么记录 |
| --- | --- |
| 场景几何、地面、材质 | 网格 + PBR 材质（白膜场景同样导出）；不受光材质用 `KHR_materials_unlit` |
| 人物 | 保留关节层级（`<id>_hips / _chest / _upperarm_L / _forearm_L / _thigh_L / _shin_L / _head …`），每个关节的旋转、根节点走位逐帧关键帧；方块躯干是两根骨骼的蒙皮网格，弯腰扭转照样还原；动作捕捉片段、IK 接触、微动呼吸都已烘焙进去 |
| 道具 | `PROP_<id>`，按世界坐标逐帧记录，所以换手、落地、作弊挪位都不会跳；隐藏 = 缩放到 0（阶跃） |
| 结构动画、特效小件 | 倒塌的台面、移动的灯带、钢索钉头等按本地坐标逐帧；钢索线换成细圆柱 `FX_cable_n` |
| 镜头 | 每镜一台相机 `CAM_<镜头 id>`，只在本镜时间内有关键帧，含手持漂移；视角与网页 FOV 一致 |
| 灯光 | 每盏灯换成独立灯 `LIGHT_…`（位置、方向逐帧，例如枪下挂手电跟着枪走） |
| 附带数据 `extras.zpboom` | 帧率、帧数、分辨率、曝光、背景色、雾、环境光、镜头表（起止帧、焦距）、声音提示、灯光逐帧强度、发光材质闪烁 |

GLB 本身是通用格式，也能直接导进 Maya、C4D、Unreal、Unity；只有 Blender 有 `blender_setup.py` 帮你补齐下面这些设置。

## blender_setup.py 做了什么

- 先设帧率再导入 GLB（glTF 导入按当前帧率把秒换成帧），帧范围对齐网页时间线（网页 0 秒 = 时间线第一帧，通常是第 0 帧）。
- 分辨率按画幅（16:9 为 1920×1080，21:9 为 2520×1080，9:16 为 1080×1920，1:1 / 4:3 / 3:4 同导出 MP4）。
- 每台镜头相机：传感器按竖直 24mm（和网页「≈ mm」读数一致），设焦距与近远裁剪面；时间线在每镜起点打标记并绑定相机，播放 / 渲染时自动切镜。
- 声音提示打成 `♪ …` 标记。
- 灯光强度换算：网页（three.js 物理单位）点光 / 聚光强度 I → Blender 功率 4πI 瓦；平行光照度直接等于 Blender 太阳强度；是否投影、聚光角、柔边照搬；闪烁的灯（电火花）逐帧关键帧。
- 发光材质的闪烁（义眼、机械臂红灯）逐帧关键帧到「自发光强度」。
- 世界光：相机看到的背景 = 网页背景色；照亮物体的环境光 = 网页半球光 / 环境光（地面色到天空色的渐变）。
- 曝光 = log2(网页 exposure)，色彩管理用 AgX（老版本用 Filmic），渲染器 EEVEE。
- 按 人物 / 道具 / 场景 / 相机 / 灯光 / 特效 分集合，打包贴图，打开即为镜头视角 + 材质预览。

## 和网页预演的差别

- 动画是逐帧关键帧：改机位、灯光、镜头很方便；大改动作还是回网页改关键帧，再重新导出更省事。
- 网页里 `decay ≠ 2` 的灯（例如手电 1.6）在 glTF / Blender 里固定按平方衰减，导出时按“有效距离一半处亮度相同”补偿了强度，近处会略暗、远处略亮。
- 电火花、灰尘这类粒子不导出（Blender 里看不到点云），电火花的闪光灯保留；钢索是细圆柱。
- 天气：阴天 / 时间段对灯光的影响、闪电（逐帧强度的灯）照搬；雨雪由脚本建成「天气 Weather」集合里的粒子发射器（近似，雨丝样子和网页不完全一样）；雾只记在 Mist 设置里。
- 叠加发光（`additive`）材质导出为普通半透明，手电光束锥体会略淡。
- 雾记在 Blender 世界的「雾场 Mist」设置里（合成时可用），不会直接出现在画面上。
- 网页的「网格 / 角色标签 / 工作光（editorOnly）」不导出。
- Blender 用自己的渲染器，画面和网页不会逐像素一致，但机位、构图、走位、动作时间完全一致。

## 实测

Blender 4.5.15 LTS（Intel Mac）实测：三个工程生成 .blend 各约 8 秒；在 Blender 里逐帧比对关节误差小于 1 毫米，标记切镜在每个采样点都切到对应镜头。第一次用 EEVEE 渲染要先编译着色器（这台机器约 1.5 分钟），之后每帧 1080p 一半分辨率约 8 秒。导入插件会生成一个不渲染的 `glTF_not_exported` 集合，里面是骨骼显示用的小球，脚本会把它在视图里也隐藏，不要删除。

## 验证接口

`await window.__ZPBOOM_PREVIS__.exportBlender({download: false})` 只生成不下载，返回 `blob / filename / bytes / frames / fps / tracks / droppedTracks / shots / lights / cables`。`droppedTracks` 应为 0。用 three.js 的 GLTFLoader 重新载入 `blob`，按 `t = 帧 / fps` 播放动画，和 `renderAt(t)` 的 `point()`、`getState().camera` 比较即可确认烘焙结果（正常误差在 1 毫米以内）。
