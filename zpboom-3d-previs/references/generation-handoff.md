# 录制、素材绑定与生成交接

## 录制之前

保存最终 `scene.json` 和版本记录，确定总时长、帧率、画幅。按分镜完整播放一遍，检查切点和静止帧。

**首选：逐帧导出 MP4。** 点模板的「导出 MP4」按钮。工程会逐帧 seek → 渲染 → WebCodecs H.264 编码 → mp4-muxer 封装，输出 1920×1080、项目帧率、约 16Mbps 的 MP4（30 秒约 40MB）。这个方式：
- 不依赖实时性能，不掉帧；
- 网格、角色标签和编辑工作光会自动隐藏，导出后恢复；
- 需要较新的 Chrome、Edge 或 Safari（支持 WebCodecs），无需 ffmpeg；
- 页面在后台时浏览器会降速，导出变慢，但不影响帧的完整性。

验证方法：在页面里运行 `await window.__ZPBOOM_PREVIS__.exportMp4({download: false})`，它返回 `frames / width / height / codec / bytes / header` 和 `blob`。header 应为 `ftyp`。把 blob 放进 `<video>` 读取 `duration`、`videoWidth`，再 seek 到中段确认不是黑帧，才算确认导出成功。

**后备：实时 WebM。** 浏览器不支持 WebCodecs 时，按钮会自动改用 MediaRecorder 实时录制，结果可能掉帧。需要 MP4 且环境里有 ffmpeg 时，可以转码：

```bash
ffmpeg -i "previs.webm" -c:v libx264 -crf 18 -pix_fmt yuv420p -an "previs.mp4"
```

转码只改变封装和编码，补不回实时录制时丢掉的帧，也不会把几何预演变成 CG。需要音频时不要加 `-an`。没有 ffmpeg 时保留 WebM，按生成平台实际支持的格式处理，不要虚称已转换。

## 参考分工与两句核心约束

1. **参考视频只约束镜头顺序、切点、摄影机位置与路径、主体相对位置和事件先后；不迁移代理角色的逐帧骨骼、僵硬步频、滑步、关节抽动和灰色简化材质。按最终人物比例与环境重新形成自然动作。**
2. **人物、服装、专属道具和场景设计严格按对应图片绑定，角色和道具不交换；图片的棚拍背景、站姿和展示光线不带入剧情。**

这些是生成指令，不是模型效果保证。按用户片种调整，不要在产品展示里强加人物表演约束。

## 每段生成文本结构

```text
目标：长度、画幅、风格及事件摘要。
参考视频：实际上传标签；本段对应原预演的起止时间。
素材绑定：A外观→上传标签；A道具→上传标签；场景→上传标签。
参考边界：摄影与空间来自预演，设计来自图片，动作重新形成自然表演。
起止状态：承接上一段的身份/朝向/持物/门状态，结束要达到什么状态。
镜头01：本段局部时码、画面、动作、起止机位、目标点、运动意图。
镜头02：……
声音：用户需要的同期声、环境声；不需要时不添加台词。
检查：身份/道具/动作接触/切点/背景连续性。
```

`prepare_generation.py` 会生成这个骨架、素材清单和裁切计划。它读取 `action` 文字和机位数据，不能从代码自动理解未标注的剧情状态；宿主需补上实际动作接触、力学细节和跨段起止状态。缺素材用有名称的待绑定字段，交接前逐项替换成真实上传标签。

## 分段与复查

先选含代表性机位和角色互动的一段进行小范围验证。是否分段取决于事件长度、角色复杂度和当前模型入口。脚本的 `--segment-seconds` 是软性规划目标；它按更接近目标的下一个完整镜头边界贪心分组，可能略超目标并给出提示，不切碎一镜，也不裁切视频。例如三镜各6秒、目标约10秒，会规划12+6秒。若平台有硬上限，须另行检查每段并人工调整分镜，不能把软目标当硬限制。按 `clip-plan.json` 在录制文件中裁出相应时间段，再把该段与其提示词一起使用。

跨段要核对人物在队列中的位置、脸/衣服、每件道具归属、门和设备状态、时间光线、运动方向、已发生事件。若两段存在重叠，最终剪辑检查重复动作。若生成误用了别人的道具，先缩小参考段、清晰标注绑定并重写相关镜头；不靠大量堆叠泛泛的“电影感”词解决。

没有可调用生成工具时：提供上述参考文件、待上传清单和操作顺序，状态记为“待上传/待生成”。用户界面的入口名称、模型版本、时长限制应当场核对；不要预写未经验证的 API 或假装已代生成。

## 夜景、暗场：参考画面要看得清，氛围写进提示词

视频模型从参考视频里主要学构图、机位运动、人物位置与动作、事件时机；夜晚、昏暗、冷暖这些氛围主要靠提示词和风格参考图生成。参考画面太黑，模型反而看不清人物和动作。

- 网页加载和打开导出设置时会测每个镜头的亮度，低于 12% 会提示过暗。
- 「镜头」页的「参考提亮」：提高曝光、给暗部补中性光，灯光方向和冷暖不变；点「自动」会找到让每个镜头都够亮（≥20%）的最小值。只影响网页预览和「提亮参考」导出，`world` 里的故事光照、天气时间段、导出 Blender 都不变。
- 导出 MP4 的「画面」：原样光照 / 提亮参考（推荐给视频模型）/ 白膜平光（无阴影、去雾和雨雪，只看形体动作）/ 深度图（近白远黑，适合支持深度参考的模型和工具）。可以分别导出几版。
- 写提示词时把光照写清楚，例如“深夜医院走廊，顶灯冷白、间隔昏暗，病房只有窗外月光”，并说明参考视频是提亮后的，只参考构图和动作，不参考亮度。
